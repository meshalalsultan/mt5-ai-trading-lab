# Contributing

Follow [WORKFLOW.md](WORKFLOW.md). Use English for core artifacts; Arabic explanatory notes are welcome.

Create one focused issue per experiment, tool, or research question. Use a descriptive branch such as `experiment/exp-002-market-analysis`, then a pull request explaining the problem, change, evidence and remaining limits. Direct foundation commits may initialize the lab.

Use stable IDs: EXP-001, CS-001, and category-specific prompt IDs. Record the date in ISO format, actual run timezone, and commit/version used. Do not rename published IDs.

Never mark placeholders as findings or synthetic data as account history. Do not add credentials, client exports, binaries, or generated terminal caches. New MQL5 code needs its build, compile output, inputs, test method, and limitations recorded before it is called tested.

Use the issue and pull request templates. A maintainer checks evidence and publication readiness; a model's self-review alone is insufficient.
