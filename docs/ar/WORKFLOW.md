# نظام العمل اليومي

[العودة للدليل](README.md)

**نتعلّم ← نختبر ← نبني ← نتحقق ← نوثّق ← نعرض ← ننشر ← ندرس التحويل إلى منتج أو خدمة.**

القاعدة: كل يوم ينتهي بشيء ملموس، حتى لو كان توثيق تجربة فشلت. لا يلزم الوصول لمرحلة البيع في كل يوم.

## مراحل العمل

| المرحلة | ما الذي نفعله؟ | متى ننتقل؟ |
|---|---|---|
| نتعلم | نفهم المشكلة وما ينقصنا | عندما نملك سؤالًا واضحًا وفرضية |
| نختبر | ننفذ طلبًا محددًا على بيانات معروفة | بعد حفظ المدخلات والرد والبيئة |
| نبني | نحسن طلبًا أو ننشئ طريقة عمل أو أداة | عندما يوجد مخرج يمكن فحصه |
| نتحقق | نحاول كشف الأخطاء ونقارن بمصدر مستقل | بعد تسجيل التطابق والاختلاف |
| نوثق | نكتب النجاح والفشل والحدود | عندما يمكن فهم ما فعلناه وإعادته |
| نعرض | نقدم مثالًا مفهومًا | عندما يرتبط العرض بأدلة |
| ننشر | نراجع اللغة والادعاءات والمعلومات الخاصة | بعد اكتمال المراجعة |
| ندرس القيمة التجارية | نحدد من قد يستفيد وكيف نختبر الطلب | بعد فصل الفكرة عن المبيعات الفعلية |

## جدول مقترح قابل للتعديل

| الوقت بتوقيت الكويت | المهمة | المخرج |
|---|---|---|
| 09:00–09:30 | تحديد مهمة اليوم | سؤال واحد ومعيار نجاح |
| 09:30–11:30 | تنفيذ التجربة | الردود والملاحظات |
| 11:30–12:00 | حفظ الأدلة | صور أو ملفات واضحة الأسماء |
| 12:00–13:30 | بناء تحسين صغير | طلب أو طريقة عمل أو كود |
| 15:00–16:30 | التحقق | مقارنة مستقلة وتسجيل الأخطاء |
| 16:30–17:30 | التوثيق | بطاقة التجربة وتقرير اليوم |
| 17:30–18:30 | تقييم الفائدة | فكرة خدمة أو منتج قابلة للاختبار |
| آخر 15 دقيقة | إغلاق اليوم | تحديث المهمة وتحديد الخطوة التالية |

الأوقات تنظيم مقترح وليست التزامًا بما نُفّذ. نختصرها أو نوزعها حسب الحاجة.

## الحالات التي نستخدمها

- **مخطط لها:** كتبنا التجربة ولم ننفذها.
- **قيد التنفيذ:** بدأنا حفظ ردود فعلية.
- **متعطلة:** بيانات أو وصول ضروري غير متاح.
- **تم التحقق ضمن النطاق:** اجتازت المعايير المحددة في بيئتها فقط.
- **فشلت:** لم تحقق معيار النجاح، مع توثيق السبب.
- **غير حاسمة:** الأدلة لا تكفي للحكم.
- **مغلقة بحدود:** انتهت الجولة ووثّقنا حدودها؛ لا يعني ذلك نجاح كل الفرضيات.

مثالنا: أُغلقت جولة الحساب بلا سجل تداول، لكن التشخيص على تاريخ صفقات فعلي بقي غير مختبر.

## كيف نحفظ الدليل؟

اسم مثل EXP001-02-Data-Access يربط الدليل بالتجربة ومرحلتها. نسجل معه التاريخ، مصدره، نسخة الطلب، والجزء الذي يؤيده.

نميز بين:
- ملاحظة شاهدها المستخدم في المنصة.
- تقرير كتبه مساعد المنصة ونقله المستخدم.
- نتيجة راجعناها مباشرة من ملف أو صورة.
- حساب مستقل أعدناه بأنفسنا.

لا نسمّي تأكيدًا كتابيًا من المستخدم «صورة محفوظة» أو «تقريرًا راجعناه مباشرة».

## قبل إغلاق اليوم

- [ ] حددنا ما نفذناه وما لم ننفذه.
- [ ] حفظنا نص الطلب والرد، أو صرّحنا بأن الأصل غير محفوظ.
- [ ] كتبنا الأخطاء والقيود.
- [ ] وضحنا كيف تحققنا ومن قام بالمطابقة.
- [ ] أزلنا المعلومات الخاصة من أي مادة عامة.
- [ ] حدّثنا بطاقة التجربة والتقرير اليومي والمهمة.
- [ ] حددنا خطوة واحدة تالية من الخطة.

## التعامل مع الأفكار الجديدة

نكتبها في قائمة مؤجلة ولا نغير مهمة اليوم تلقائيًا. تحليل استراتيجية وتحسين معاملاتها لا يصبح بديلًا لتجربة تشخيص الحساب لمجرد ظهور تقرير مثير للاهتمام.

## التعديل والمشاركة

نسجل كل تغيير مع سببه. نحافظ على أرقام التجارب والروابط. عند اقتراح كود جديد نذكر إصدار المنصة ونتيجة التجميع والاختبار والحدود. عند تجهيز عرض للشركات نستخدم النتيجة النهائية المدعومة، لا كل فرضية مررنا بها.
