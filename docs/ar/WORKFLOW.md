# نظام العمل — مخرج يفيد المستخدم
[الأهداف](GOALS.md) · [خطة المنتج](../../products/prompt-pack/PRODUCT-PLAN.ar.md)

**Learn → Test → Build → Validate → Document → Demonstrate → Publish → Monetize**

| المرحلة | التطبيق الحالي |
|---|---|
| Learn | مشكلة متداول محددة، لا دراسة عامة بلا مخرج |
| Test | تجربة طريقة طلب على مهمة يستخدمها المتداول |
| Build | نصوص وقالب ودليل ومثال قابل للتسليم |
| Validate | صحة المحتوى، سهولة الاستخدام، والوقت الفعلي |
| Document | وصف مختصر للمصدر والحدود والنتيجة |
| Demonstrate | عرض عملي يرى فيه المشاهد كيف يستفيد |
| Publish | مادة واضحة بعد إزالة البيانات الخاصة |
| Monetize | عرض محدد وتسليم ومتابعة طلبات وشراء فعلي |

## يوم الإنتاج
- 15 دقيقة: مخرج اليوم وحده ومعيار اكتماله.
- نحو 3 ساعات: إنتاج الأصل.
- حتى ساعة: مراجعة محتوى واستخدام، لا اختبارات بنية منصة.
- الوقت المتبقي من سقف 5 ساعات: تجهيز العرض التجاري وتوثيق مختصر وإغلاق اليوم.
- ننهي مبكرًا عندما يكتمل المخرج. لا نملأ اليوم ببحث إضافي.

## ضوابط تمنع التشتت
ميزة واحدة تعطل المنتج: نحذفها أو نبسطها بدل فتح سلسلة إصلاح. لا ندعي قدرة لم تُشاهد، ولا ننشر خطأ مؤثرًا لتوفير الوقت.
مراجعة واحدة وجولة مستخدمين واحدة وتحسين واحد في هذه الدورة. بعد ذلك قرار منتج صريح.
أي فكرة أخرى تُسجل كمؤجلة، ولا تغيّر مهمة اليوم.

## تعريف الإنجاز
يوجد ملف/عرض يستطيع مستخدم مقصود استعماله؛ تعليماته واضحة؛ محتواه مراجع؛ حالته وحدوده صريحة؛ والخطوة المؤدية للتوزيع أو العميل محددة. تقرير تقني إضافي وحده لا يحقق معيار اليوم.

## الأمانة المهنية
نفصل ما صمّمناه عما جرّبناه وما اشتراه مستخدم. لا نحول وقتًا موفرًا إلى وعد ربح. لا ننشر بيانات حساب شخصية، ولا ننسب للمساعد وصولًا غير متاح. التاريخ والأدلة القديمة محفوظة؛ لا نعيد صياغة نتائجها لتبدو أفضل.

## إغلاق اليوم
اكتب خمسة أسطر: ماذا سلّمنا؟ لمن يفيد؟ ماذا تحقق؟ ماذا بقي؟ ما المهمة التالية؟
لا طلب تشغيل تقني جديد من مشعل إلا إذا اختاره صراحة لغرض منتج محدد.
